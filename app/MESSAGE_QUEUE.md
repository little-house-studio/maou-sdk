# 消息队列机制与交互

消息由服务端会话队列持有。前端展示服务端快照，并保存尚未确认成功的草稿；浏览器不再通过“先删除、再发送”消费队列。

## 用户行为

- 运行中发送文本：入队，普通消息在安全的轮次边界按顺序交给模型；同一边界可接收多条消息。
- 插入：原子地修改原消息的投递模式，打断该会话当前回复，优先处理插入消息。不会删除后重新入队，也不会提前取走普通排队消息。
- 编辑与排序：仅能修改尚未被领取的消息，保留队列 ID。消息已经开始处理时，刷新队列并明确提示。
- 停止：终止当前回复，保留尚未领取的队列项。停止完成后可点击“继续发送”。
- 继续发送：服务端在会话运行锁内领取下一条，流式返回处理结果，再继续领取剩余消息。错误会暂停后续领取。
- 清空：内联确认，只移除确认列表中的待处理消息，保留失败草稿和其他窗口后来加入的消息。
- 入队失败：直接显示原因；重试复用请求 ID，避免网络确认丢失造成重复入队。
- 重新打开会话：同步服务端队列。未确认和失败草稿保存在当前浏览器标签的 sessionStorage，供手动恢复。

界面支持折叠、展开完整文本、内联编辑、上下移动、可见焦点、Escape 取消编辑、⌘/Ctrl+Enter 保存，以及窄窗口布局。编辑框正确处理中文输入法组合状态。

## 一致性约束

1. 每次队列操作携带 sessionId，拒绝迟到请求修改已切换的会话。
2. 消息身份使用 queueId / requestId，绝不按文本合并；相同文本可以分别排队。
3. 同一前端的修改串行提交；快照使用会话代数、变更版本和请求序号过滤迟到响应。
4. 消费通知先于 HTTP 确认到达时，消费记录防止旧响应复活消息。
5. 单会话容量为 64。满额拒绝新消息，原有消息保持完整，失败输入仍可重试。
6. 单会话单消费者；停止后保留运行锁直至生成器退出，避免续发与旧回复重叠。
7. 共享队列按会话绑定运行实例的打断回调，并在生成器退出时解绑。
8. App 的运行退出由 AgentHub 接管队列续跑，避免仅将消息写入历史却没有实际回复。

接口：`POST /api/chat/enqueue`、`GET/DELETE /api/chat/queue`、`PATCH/DELETE /api/chat/queue/:id`。续发使用 `POST /api/chat` 的 `resumeQueue: true`；停止使用 `POST /api/chat/abort` 的 `keepQueue: true`。删除已消费消息返回正常响应及 `removed: false`。

## 当前边界

服务端队列仍为进程内队列，不承诺应用进程重启后的持久恢复。去重保留最近 10,000 个已接收请求；仍在队列中的请求始终可去重。已经领取、开始执行的消息不再属于可编辑队列，模型或工具执行不具备跨进程 exactly-once 保证。队列仅接受文本，图片在当前回复和排队结束后发送。

验证使用真实 React 组件、浏览器交互以及队列/AgentHub 行为测试；浏览器模型流使用可控替身，不调用外部模型。
